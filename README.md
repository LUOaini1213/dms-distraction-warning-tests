# 座舱 DMS 与分心预警：从 ADDW / Euro NCAP 条款到可测试的报警逻辑

把欧盟 ADDW / DDAW、Euro NCAP 2026 驾驶员参与度规程、ASEAN NCAP 2026–2030 和 NHTSA 视觉-手动指南的条款整理成需求（共 56 条），再写成一个 Python 驾驶员监测（DMS）逻辑包 `dms/`，用合成场景按规程程序逐条测试。链路是：**条款 → 需求 → 场景测试 → 结果**，并做双向追溯。

> **个人项目，使用 AI 工具辅助完成。** 所有场景数据都是合成数据（SYNTHETIC），所有阈值要么注明条款，要么标为设计假设（DA-xx）。本项目**不声称**任何车辆或功能符合 ADDW、DDAW 或 Euro NCAP。完整报告见 [report.md](report.md)，需求见 [需求规格.md](需求规格.md)。

## 调研中对设计影响最大的结论

只读官方来源（条款和链接见 `regulation_requirements.csv`，119 条已核实、1 条未核实）：

- **ADDW（EU 2023/2590）只管长时单次注视**：车速 ≥50 km/h 时注视 Area 3（眼点向下 30° 以下）最多 3.5 s、≥20 km/h 时最多 6 s 就要报警（Annex I Part 1 §3.3.2.1/§3.3.2.2）。累计扫视要等到 2027 年 7 月前的下一阶段（序言 (3)）。2026-07-07 起所有新 M/N 类车辆强制（解释备忘录 §1）。
- **ADDW 的报警起点是声音或触觉**（§3.4.1.1），只亮视觉灯不算；后视镜、仪表一般不在 Area 3。
- **Euro NCAP 2026 比 ADDW 严**：≥20 km/h 就要求 3–4 s 报警（DE v1.2 §1.2.1），还要求 VATS（30 s 内累计 10 s，§1.2.2）、手机使用、微睡眠 1–2 s、睡眠 ≥3 s；墨镜等导致不能工作时要在 10 s 内提示（§1.1.1.2）。驾驶相关注视只给干预分，不给报警分（§1.4 表）。
- **ASEAN NCAP 2026–2030 没有 DMS 性能试验**：驾驶员状态监测只是 Safety Assist 里一项可选 Advanced SAT 的功能定义（SA v3.2 §7.2.4），按装配给分，每项 1 分、该节上限 2 分，不做场地试验（§7.3.1–§7.5）。IVASA 有一个简单的座舱 DMS 试验（注视 5 s、闭眼 5 s），但它是星级之外的独立项目。
- **DDAW（EU 2021/1341）以车辆信号分析为主**（转向、车道位置，Annex I §3.3.2），KSS ≥8 必须报警（§3.3.1）；PERCLOS 只是验证时可用的替代测量（Part 2 §5.2.1(a)），没有阈值。
- **NHTSA（2013）**：至少 21/24 名受试者满足 >2.0 s 扫视 ≤15 %（向上取整）、平均扫视 ≤2.0 s、总离路时间 ≤12.0 s（VI.E.14）；第一阶段只覆盖视觉-手动交互。
- **GB/T 41797-2022**：现行推荐性国家标准（2023-05-01 实施），技术条款未能读到，标为【未核实】。

## 设计要点（PROPOSED）

- **一个 3.3 s 阈值，所有车速 ≥20 km/h 通用**：同时满足 ADDW（≤3.5 s）和 Euro NCAP（3–4 s），并给端到端时延留 0.2 s。边界扫描显示：时延 ≤0.3 s 才能落在 Euro NCAP 的 ±0.2 s 窗内，≤0.7 s 才能满足 ADDW 试验的 4.0 s 上限。
- **VATS 按 Euro NCAP 实现**：30 s 窗内累计 10 s；连续注视道路 2.0 s 结束本轮累计。
- **后视镜、仪表不报警**，但连续离开道路 0.8 s 就请求 FCW/AEB 提高灵敏度。
- **中断容差 0.3 s**（法规最小 50 ms）：眨眼和图像伪影不打断计时；超过 0.3 s 的 unknown 冻结、不复位。
- **逐级升级**：视觉预警 2.0 s → 声音 3.3 s → 触觉（声音后 1.5 s 未消除，或 60 s 内重复报警）。
- **一次只发一个提示**（GSR Art. 6(3)）：无响应 > 睡眠 > 微睡眠 > 分心 > 疲劳；被压住的疲劳报警延后补发。
- **传感器不可用**：人脸丢失或墨镜 5 s 后提示；测不到光 1 s 后点亮恒定故障指示（ADDW §3.5）。

## 误报研究（合成自然驾驶，4 h / 配置，每种配置 32 个注入分心事件）

合成模型里专门加入了“位置是 off_road、但其实在开车”的路口左右扫视和汇入回头看。误报按真实活动判定。

| 配置 | 误报 /h | 正确但可能扰人 /h | 视觉预警 /h | 长注视按时（ADDW / NCAP） | 手机 VATS 检出 / 按时 | VATS 中位时延 |
|---|---:|---:|---:|---|---|---:|
| **PROPOSED** | **0** | 0.25 | 23.3 | 100 % / 100 % | 100 % / 100 % | 15.6 s |
| ADDW_MIN | 0 | 0.25 | 0 | 85.7 % / 81.2 % | 0 % / 0 % | — |
| T_long = 3.0 s | 0.25 | 1.00 | 23.3 | 100 % / 100 % | 100 % / 100 % | 15.6 s |
| T_long = 3.5 s | 0 | 0.25 | 23.3 | 92.9 % / 100 % | 100 % / 100 % | 15.6 s |
| 复位 = 1.0 s | 0 | 0.25 | 27.8 | 100 % / 100 % | 31.2 % / 6.2 % | 19.8 s |
| 容差 = 0.05 s | 0 | 0.25 | 21.0 | 92.9 % / 93.8 % | 100 % / 100 % | 15.6 s |
| 容差 = 0.6 s | **7.25** | 0.25 | 31.5 | 100 % / 100 % | 100 % / 100 % | 14.9 s |
| 视觉预警 = 2.5 s | 0 | 0.25 | 13.3 | 100 % / 100 % | 100 % / 100 % | 15.6 s |

- 容差放宽到 0.6 s 时，29 次误报里有 20 次来自路口扫视和回头看（中间 0.5 s 的路面注视被“吃掉”，几次短扫视拼成一次长注视）。
- 容差收紧到 0.05 s、或阈值提到 3.5 s 时，一个夹带感知噪声的 4.8 s 注视（102 km/h）报警晚于 4.0 s。0.3 s 容差加 3.3 s 阈值正好避开两边。
- 视觉预警每小时 23 次，可能被驾驶员当成打扰；改成 2.5 s 可降到 13 次。这需要 HMI 主观评价来定。
- 误报绝对值只在本合成模型内有意义，见“局限”。全部 12 种配置见 `results/false_alarm_summary.csv` 和图 2。

## NHTSA：导航目的地输入的 HMI 取舍（合成扫视模型，24 人）

| 方案 | (a) >2 s 扫视 ≤15 % | (b) 平均 ≤2.0 s | (c) 总离路 ≤12 s | 结论 | 总离路时间中位 / 最大 | DMS 报警的受试者 |
|---|---:|---:|---:|---|---|---:|
| 触屏输入地址 | 16/24 | 23/24 | 2/24 | 不可接受 → 行驶中锁止 | 13.6 / 23.6 s | 24/24 |
| 语音输入地址 | 24/24 | 23/24 | 24/24 | 可接受 | 2.9 / 6.8 s | 0/24 |
| 触屏选收藏地址 | 23/24 | 24/24 | 24/24 | 可接受 | 4.6 / 7.4 s | 0/24 |

触屏输入地址卡在总离路时间（12 s），这正好也会触发 DMS 的 VATS 报警（30 s 内累计 10 s）。Euro NCAP DE §2.3.3 要求导航到地址用直接语音输入。语音方案只评估了它残留的视觉-手动部分，因为 NHTSA 第一阶段不覆盖语音交互。

## 怎么做的

1. **调研**：EUR-Lex 对抓取工具只返回空页，所以 ADDW 读的是理事会登记的 Commission 通过文本 C(2023) 4523 final，DDAW 读的是 EFTA 发布的 EEA 官方挪威语译本，GSR 读的是 PE-CONS 82/19 最终文本；Euro NCAP、ASEAN NCAP、NHTSA（govinfo.gov）都是官方 PDF。每个数字在 `dms/regulations.py` 注明条款。
2. **需求**：`需求规格.md` 共 56 条，含报警升级、抑制、复位表，以及 23 项设计假设。
3. **逻辑**：`dms/` 按 ECU 任务的方式逐帧运行（30 Hz，整数帧计数），核心是 `detectors.py`（长注视、VATS、离路计时、PERCLOS、可用性）和 `warning.py`（升级、抑制、仲裁、ADAS 联动）。
4. **测试**：`suites.py` 按 ADDW Part 2、Euro NCAP SD-202 和 IVASA 的程序生成用例，另有 43 个边界用例；`false_alarm.py` 做误报研究，`nhtsa.py` 做 HMI 任务评估，`ddaw.py` 实现 DDAW Part 2 的判定和有效性计算。
5. **追溯**：`dms/requirements.py` 是需求注册表；单元测试用文档字符串里的 `REQ:` 行声明它验证哪条需求；`dms/trace.py` 生成 `traceability.csv`，并检查两个方向都没有孤立项。

## 复现

在本目录下运行（Windows 与 Linux 相同；依赖 numpy、pandas、matplotlib、pytest）：

```bash
python -I scripts/run_all.py                                       # 全部结果、图和追溯矩阵，约 1.5–2.5 分钟
python -I -m pytest -q tests --junitxml=results/pytest_junit.xml   # 40 项
python -I scripts/make_traceability.py                             # 把单元测试判定写进追溯矩阵
```

代码只用相对路径（`pathlib`），随机数都固定种子，重复运行结果一致。

## 局限

- **只是逻辑层**：输入是“已经分好类的注视标签”。真实 DMS 的难点（暗光、红外反光、墨镜、头部大角度、不同人群）都在感知层，本项目没有覆盖，只用标签噪声粗略模拟。
- **全部是合成数据**：扫视模型、感知噪声、NHTSA 任务模型、DDAW 演示里的 KSS 模型都是设计假设，没有用自然驾驶数据或真人试验标定。误报率、时延的绝对值不能外推；能看的是参数之间的相对取舍。
- **疲劳阈值未标定**：PERCLOS 0.12 / 0.20 只是假设；DDAW 型式认证需要按 Part 2 用 ≥10 名真人做验证，还要以车辆信号分析为主。
- **规程判定口径**：Euro NCAP SD-202 的容差示意图未能读取，长时分心按 ±0.2 s 判定；DDAW 的标准差公式按译文重建。
- **不在范围**：HMI 声学参数、EF 紧急停车、FSS 对 AEB 的真实效果（需与 P5 的 AEB 闭环联调）、跨上电的故障存储、ECU 自检与诊断。

## 未核实

- ADDW 的 OJ 公布版本与所读 C(2023) 4523 final 是否逐字一致；DDAW 的英文原文。
- ADDW §3.3.1.1 中 Area 1 “overlap” 的含义；SD-202 方括号暂定值与容差判定口径；DDAW §8.1 标准差分母。
- GB/T 41797-2022 的全部技术条款。
- 全部 23 项设计假设，尤其是 PERCLOS 与 KSS 的对应（DA-12）和合成驾驶模型（DA-19）。
